- **Contexte** : sur le casque, besoin de threads, de files bornées et de sérialisation fiables, hors GC. Sur le PC, l'entraînement est en Python (ADR-008) et l'ingest traite au plus quelques dizaines de messages lourds par seconde.
- **Décision** : `mote-core` en Rust (`cargo-ndk`, `cbindgen` pour le header C). Ingest, entraînement, évaluation et outils dans un seul paquet Python. `[DECISION]`
- **Alternatives** : C++ pour le core (concurrence et sérialisation plus fragiles) ; ingest en Rust (version 0.1 : partage de code avec le core, mais ajoute une frontière inter-processus non spécifiée entre ingest et entraînement, sans besoin de performance).
- **Conséquences** : le schéma protobuf est le seul contrat partagé entre casque et PC ; le core n'ayant plus d'accès matériel, il ne dépend d'aucun binding NDK.
- **Remise en cause si** : l'ingest Python ne tient pas le débit du pire cas (6.2) au profilage.
