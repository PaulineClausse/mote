### 7.1 Vue d'ensemble

```
+-------------------------------------------------+
| Hôte Unity (C#, package UPM)                    |
| acquisition MRUK : paires + pose par frame,     |
| pose casque, profondeur, événements de tracking |
| UI de couverture                                |
+------------------------+------------------------+
                         | P/Invoke (API C, tout en push)
                         v
+-------------------------------------------------+
| mote-core (Rust, libmote.so arm64)              |
| sélection des paires -> JPEG -> MCAP local      |
| (source de vérité) -> flux live + rattrapage    |
+------------------------+------------------------+
                         | TCP, trames Envelope (protobuf)
                         v
+-------------------------------------------------+
| mote (paquet Python, PC)                        |
|  ingest : réception -> MCAP -> décodage ->      |
|           conversion de repère -> dataset       |
|  train  : init A..E -> incrémental -> final     |
|  eval / export / outils de validation           |
+-------------------------------------------------+
```

### 7.2 Composants

| Composant | Langage | Responsabilités | Dépend de |
|---|---|---|---|
| `proto/` | protobuf | Schémas de tous les messages | rien |
| `mote-core` | Rust | Sélection des paires, score de netteté, encodage JPEG, écriture MCAP, transport live et rattrapage, statistiques, API C. Aucun accès au matériel ni au moteur : compilable et testable sur PC. | `proto/` |
| `hosts/unity` | C# (package UPM) | Permissions, acquisition MRUK (caméras, pose par frame, intrinsèques), pose du casque, lecture de la profondeur, appariement gauche/droite, événements de tracking, wrapper P/Invoke, calcul et affichage de la couverture | `mote-core` |
| `pc/mote/ingest` | Python | Serveur de réception, écriture MCAP, demandes de rattrapage, décodage, conversion de repère, recalage profondeur, publication du dataset incrémental | `proto/` |
| `pc/mote/train` | Python | Initialisations, entraînement incrémental et final, aperçu live | dataset |
| `pc/mote/eval`, `pc/mote/tools` | Python | Évaluation, exports, validation des repères, rapports | MCAP, dataset |

### 7.3 Frontières et responsabilités clés

- **L'hôte acquiert, le core traite.** L'hôte possède la session XR, les caméras et la profondeur ; il pousse tout au core (`mote_push_*`). Le core possède la sélection, l'encodage, le fichier et le réseau. `[DECISION]` ADR-002, ADR-011.
- **Un seul référentiel de temps**, `CLOCK_MONOTONIC` du casque (9.3).
- **Une seule source de vérité par session** : le MCAP du casque (ADR-012).
- **Interface ingest vers entraînement** : un répertoire de dataset en ajout seul (images décodées, `frames.jsonl` avec poses canoniques et intrinsèques, nuages d'init). L'entraîneur le suit pendant le scan et peut être relancé dessus hors ligne. L'ingest peut le reconstruire à l'identique depuis le MCAP (NFR-07).
- **Calcul de couverture** : dans l'hôte Unity en v1 (profondeur et poses y sont déjà disponibles), sur le modèle de SRC-1 et SRC-2.
