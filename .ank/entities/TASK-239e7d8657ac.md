Constaté pendant WP-07 (2026-10-13). Le code Python généré de mote.v1 (grpcio-tools 1.84.0, WP-01) exige le runtime protobuf >= 7.35.1 ; nerfstudio 1.1.5 (ADR-da6e, entraînement hors ligne, SP-0) déclare `protobuf !=3.20.0,<=3.20.3`. Dans un même environnement, `from mote.v1 import mote_pb2` échoue (`cannot import name 'runtime_version'`). ADR-8d03 prévoit un seul paquet Python sous pc/ pour l'ingest, l'entraînement et l'évaluation.

Pistes, à trancher par une ADR si la décision engage la structure :
- entraînement dans un processus et un environnement à part, qui ne lit que le répertoire de dataset (interface de SPEC-3d2a §7.3, sans protobuf) ; c'est déjà le cas des spikes SP-0 et SP-6 ;
- gsplat seul pour l'entraînement (SP-6 l'utilise sans nerfstudio), si la passe finale peut s'en passer ;
- version de nerfstudio plus récente sans cette borne, si elle existe ;
- code généré pour protobuf 3.20 : à écarter a priori, les runtimes protobuf >= 4.21 refusent l'ancien code généré.

Le test pc/tests/test_nerfstudio_load.py contourne déjà le conflit en chargeant l'export dans un processus à part.
